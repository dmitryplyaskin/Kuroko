# Фронтенд Kuroko

Устройство модулей и точки расширения описаны в [гайде по архитектуре фронтенда](../../docs/frontend-architecture.md).

## Модули и модели

- Держите компоненты, модели и запросы рядом с фичей, которой они принадлежат. `app/` отвечает за оболочку, `core/` собирает встроенные модули, `platform/` содержит общие сервисы приложения, `shared/` — переиспользуемый UI и технические утилиты.
- Если одна фича зависит от другой, используйте явно экспортируемый интерфейс владельца. Проверяйте направление зависимости при добавлении такого импорта. Общий код должен иметь одного владельца, а зависимости между фичами должны оставаться однонаправленными.
- У каждого состояния один источник истины. Черновики с правилами валидации, запросы, статусы сохранения и обработка результатов принадлежат модели фичи. Компоненты читают состояние и отправляют события через `useUnit`. Фокус, раскрытие меню и выбор локальной вкладки можно хранить в React.
- Для запросов аккаунта используйте помощники из `platform/session/request.ts`. При выходе сбрасывайте данные аккаунта и проверяйте принадлежность результата активной сессии перед применением.

## Общие компоненты и шаблоны

- Перед созданием компонента проверьте Mantine, существующие компоненты в `shared/` и шаблоны интерфейса. Выделяйте общий компонент, когда несколько экранов используют один и тот же паттерн поведения и отображения. Настройки конкретной фичи остаются у её владельца.
- Переиспользуйте поведение заголовков страниц, вкладок, панелей действий и редакторов, где совпадает сценарий. Согласовывайте состояния загрузки, пустого результата, ошибки с повтором, сохранения и выхода с несохранёнными изменениями.
- Описывайте общие компоненты и шаблоны в [каталоге UI](../../docs/frontend-ui.md). Для каждого указывайте назначение, путь к реализации и пример использования. Обновляйте запись при изменении общего поведения или интерфейса компонента.

## Расширения

- Регистрируйте экраны, вкладки настроек и другие расширения через `module.ts` и реестр. Используйте стабильные идентификаторы модулей и их записей.
- Добавляйте типизированные слоты под конкретные сценарии расширения. Контракт и место отображения принадлежат фиче, которая принимает расширение. Описывайте доступные данные и действия, жизненный цикл и то, что увидит пользователь при ошибке расширения.

## Стили, дизайн и тексты

- Для локальных стилей используйте CSS Modules. У глобальных классов конкретной фичи должен быть префикс этой фичи. Для поддерживаемой CSS-кастомизации документируйте стабильные `data-*`-атрибуты и CSS-переменные. Используйте переменные темы `--kr-*` для общих цветов, шрифтов и скруглений.
- При работе над дизайном используйте скилл `unslop`.
- Добавляйте пользовательские тексты в оба словаря, `ru` и `en`, и получайте перевод через `useI18n`. Храните ошибки в моделях как коды и переводите при отображении.

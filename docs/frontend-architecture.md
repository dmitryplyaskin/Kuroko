# Архитектура фронтенда Kuroko

Фронтенд Kuroko состоит из оболочки и продуктовых модулей. Встроенный набор `kuroko.core` подключает штатные возможности через типизированные точки расширения. Новый экран или вкладка добавляются через запись модуля, из которой оболочка получает данные для навигации и отображения.

Встроенные модули входят в сборку Vite, а `kuroko.core` регистрируется в точке запуска. Сторонние пакеты, их установка и публичный SDK относятся к следующему этапу.

## Владение кодом и зависимости

| Часть | Ответственность |
| --- | --- |
| `apps/web/src/app/` | Запуск React и Effector, гостевой экран, оболочка рабочего пространства, навигация и отображение записей реестра. |
| `apps/web/src/platform/` | Общие сервисы приложения. Сессия сообщает о входе и выходе, предоставляет текущего пользователя и привязывает запросы к активной сессии. |
| `apps/web/src/modules/` | Типы модулей, контракты точек расширения, проверка и сборка реестра. |
| `apps/web/src/core/` | Состав встроенного набора `kuroko.core`. |
| `apps/web/src/features/` | Экраны, модели Effector, API-клиенты конкретных функций и их записи для реестра. |
| `apps/web/src/shared/` | Переиспользуемые компоненты, стили и технические утилиты. |

Точка запуска собирает `kuroko.core` и передаёт реестр оболочке. Импорты конкретных модулей для сборки набора находятся в `core/`. Оболочка получает метаданные и загрузчики из реестра. Общие для функций сервисы доступны через небольшие интерфейсы в `platform/`. Технические утилиты и компоненты в `shared/` используются независимо от оболочки и продуктовых модулей.

Держите модель, компоненты и запросы рядом с функцией, которая ими владеет. Если другой модуль действительно должен вызвать её операцию или прочитать её состояние, опишите узкий интерфейс у владельца и свяжите стороны в точке сборки. Например, модуль может предоставить команду или чтение конкретного значения. Внутренние сторы и события остаются деталями реализации. Прямой вызов через такой интерфейс подходит для запроса или команды, а типизированное событие — для факта, на который могут независимо реагировать несколько модулей.

Контракты HTTP и их валидация живут в `packages/contracts`. Изменение формата запроса или ответа начинается там. Сервер на Express проверяет права доступа и управляет записью в SQLite. Модуль фронтенда пользуется клиентом API, а операции с ключами провайдеров выполняет сервер.

## Реестр и точки расширения

У каждого модуля есть стабильный ID. Запись расширения принадлежит модулю и имеет собственный стабильный ID. Встроенные модули используют префикс `kuroko.`. Ключ вкладки, адрес экрана и отображаемый текст хранятся отдельно от ID, чтобы изменение подписи или адреса не меняло идентичность записи.

| Точка расширения | Что объявляет модуль | Как использует оболочка |
| --- | --- | --- |
| Экран рабочего пространства | ID, hash-маршрут, подпись меню и порядок. Отдельный заголовок страницы, иконка и режим размещения задаются при необходимости. | Из одной записи строит ссылку в меню, определяет активный экран и заголовок страницы. |
| Вкладка настроек | ID, ключ вкладки, подпись, описание при необходимости и порядок. | Строит список вкладок и рендерит содержимое выбранной. |

Метаданные записи описывают размещение и могут быть представлены обычными данными. Загрузчик React-компонента связывается с записью по ID. Оболочка работает с уже собранным реестром, поэтому ей достаточно одинаково обрабатывать записи из разных источников.

При запуске реестр проверяет уникальность ID модулей и записей, маршрутов и ключей вкладок. Каждый экран и каждая вкладка должны иметь загрузчик. Порядок задаётся явно, а совпадения порядка разрешаются по ID. Состав `kuroko.core` указывает стартовый экран и вкладку по умолчанию. Неизвестный маршрут возвращает к стартовому экрану. Ошибка загрузки показывается в области экрана или вкладки, сохраняя доступ к навигации.

Добавляйте следующую точку расширения там, где она нужна продукту. Например, если модулям понадобится добавлять действия к сообщению, контракт определит, какие данные получает действие и как вызывается. Владелец области отвечает за размещение, порядок и поведение при пустом списке.

## Жизненный цикл и состояние

| Этап | Правило |
| --- | --- |
| Запуск приложения | Загрузите описания встроенных модулей и соберите реестр. Подключите модели, которые слушают события запуска и сессии, до отправки `appStarted` в scope Effector. |
| Вход и выход | Модуль загружает нужные данные при входе и сбрасывает данные аккаунта при выходе. Отменяйте связанные запросы и проверяйте, что результат относится к той же сессии перед его применением. Повторный вход в тот же аккаунт создаёт новую сессию. |
| Открытие и скрытие экрана | Загружайте UI по необходимости. Обычно экран или вкладка размонтируются при уходе. Если интерфейсу нужно сохранить локальное состояние, запись экрана явно выбирает сохранение после первого открытия. При скрытии освобождайте подписки и приостанавливайте работу, которая нужна только видимому экрану. |

Состояние функции хранится в её моделях Effector. Компоненты читают его и отправляют события через `useUnit`. Реестр собирается один раз при запуске. При импорте описания модуля допустимо определить модели и их связи. Запросы, таймеры и подписки на браузер запускаются на подходящем этапе жизненного цикла, где ими можно управлять и освобождать ресурсы.

Чат и настройки чата входят в один модуль. Он объявляет экран и вкладку, при входе загружает применённые настройки и при первом открытии загружает UI чата. Черновик настроек применяется после сохранения. Скрытие чата сохраняет состояние интерфейса и приостанавливает симуляцию ответа. Выход очищает состояние аккаунта и отменяет его запросы. ## Добавление модуля

1. Определите владельца функции. Если экран, вкладка или действие использует тот же жизненный цикл и модель данных, добавьте его к существующему модулю.
2. Для самостоятельной функции создайте каталог в `features/`. Опишите её в `module.ts` и разместите там только метаданные, связи с сервисами и загрузчики UI.
3. Включите модуль в `kuroko.core`. Компоненты оболочки меняются, когда появилась новая точка расширения или меняется поведение самой оболочки.

В примере `features/notes/module.ts` регистрирует экран и вкладку. Каждый загрузчик открывает компонент, экспортированный по умолчанию из своего файла.

```ts
import type { WebModule } from '../../modules/contracts'

export const notesModule = {
  id: 'kuroko.notes',
  contributions: [
    {
      kind: 'workspace.screen',
      id: 'kuroko.notes.index',
      route: '#notes',
      label: 'Заметки',
      order: 40,
    },
    {
      kind: 'settings.tab',
      id: 'kuroko.notes.preferences',
      key: 'notes',
      label: 'Заметки',
      order: 40,
    },
  ],
  views: {
    'kuroko.notes.index': () => import('./NotesPage'),
    'kuroko.notes.preferences': () => import('./NotesPreferences'),
  },
} satisfies WebModule
```

## Состав встроенных модулей

«Сцены» задают стартовый экран. Ссылки `#appearance` и `#secrets` объявлены в наборе как совместимые адреса для страницы настроек. Внешний вид регистрирует вкладку настроек, а провайдер темы применяется ко всему приложению, включая гостевые экраны.

## Проверка изменений

- Соберите для теста приложение с дополнительным встроенным модулем вне `kuroko.core`. Его экран и вкладка должны появиться через точку сборки без ручного добавления в оболочку.
- Проверьте прямые ссылки, переходы «Назад» и «Вперёд», неизвестный адрес и старый `#secrets`. Ошибка загрузки экрана должна оставлять меню доступным.
- Проверьте восстановление сессии, выход, повторный вход в тот же аккаунт и поздний ответ от предыдущей сессии. Для чата проверьте переключение экрана, продолжение ответа и применение настроек после сохранения. Используйте существующие тесты Effector через `fork` и `allSettled`. [Тесты моделей](../apps/web/src/app/models.test.ts)
- Запустите `bun run lint`, `bun run typecheck` и `bun test`. При изменениях запуска или ленивой загрузки проверьте также `bun run build`.

## Граница для сторонних плагинов

Будущий загрузчик читает локальные пакеты и приводит проверенные метаданные к формату реестра. Выбор способа выполнения остаётся на стороне загрузчика. Встроенный модуль использует ленивый импорт React-компонента, а самостоятельно устанавливаемый пакет сможет предоставить для той же точки расширения декларативный интерфейс или изолированный экран. Публичный контракт будет версионироваться отдельно от внутренних типов Effector, React и API Kuroko.

Доступ внешнего кода к данным будет проходить через разрешённые операции хоста с проверкой прав. Границы будущего SDK определит первый сторонний плагин с конкретным сценарием. Для первого этапа достаточно проверить общий путь регистрации на штатных и дополнительных встроенных модулях.

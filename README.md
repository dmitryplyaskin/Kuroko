# Kuroko

Проект на Bun и TypeScript. API работает на Express, фронтенд — на Vite, React, Effector и Mantine UI.

## Быстрый старт

Понадобится Bun 1.4.5 или новее. Выполните из корня проекта.

```sh
bun install
bun run dev
```

- Фронтенд открывается по адресу <http://localhost:5173>.
- API отвечает по адресу <http://localhost:3000/api/health>. В режиме разработки Vite проксирует запросы `/api` с фронтенда.
- Чтобы изменить порт API, скопируйте `.env.example` в `.env` в корне проекта и задайте `PORT`. Перезапустите процессы после изменения.

При первом открытии нажмите «Зарегистрироваться», создайте аккаунт и войдите с именем и паролем. С галочкой «Автовход» браузер запоминает сессию на 30 дней. Без галочки используется сессионная cookie, которую браузер хранит до конца своей сессии, а сервер принимает до 24 часов. Кнопка «Выйти» сразу отзывает текущую сессию.

Нажмите на имя или аватар в боковой панели, чтобы открыть профиль. В профиле можно выйти, сменить пароль или удалить аккаунт. Для смены пароля нужен текущий пароль. После смены все сессии завершаются. Для удаления введите имя аккаунта и текущий пароль. Вместе с аккаунтом удаляются его секреты и сессии.

## Внешний вид

В «Настройках» можно выбрать светлую, тёмную или системную тему и изменить цвет акцента. Выбор сохраняется в браузере и применяется к экрану входа. Боковое меню можно свернуть кнопкой рядом с логотипом. В разделе «Сцены» показан пример ролевого диалога и его контекста.

Язык интерфейса можно поменять на экране входа или в разделе «Настройки → Внешний вид». По умолчанию используется русский. Выбор сохраняется в браузере и применяется ко всем вкладкам приложения.

Формат `ThemeDefinition` в `apps/web/src/shared/theme/appearanceModel.ts` задаёт палитры для обоих режимов, шрифты интерфейса и текста сцен, а также скругления. Провайдер переводит эти настройки в CSS-переменные для экранов и компонентов Mantine. На этом формате можно построить редактор пользовательских тем.

## Хранение данных

В «Настройки → Подключение» можно сохранить несколько именованных пресетов с провайдером, моделью, параметрами генерации и лимитами. Значок ключа рядом с полем «API-ключ» открывает менеджер выбранного провайдера. После добавления ключа приложение показывает только его название. Один ключ можно выбрать в нескольких пресетах этого провайдера.

Для пользовательского OpenAI-совместимого API укажите базовый URL, например `https://example.com/v1`, и ID модели. Если сервер требует авторизацию, добавьте ключ в менеджере. Для API на локальном или частном адресе добавьте его origin в `.env`, например `CUSTOM_API_PRIVATE_ORIGINS=http://127.0.0.1:11434`, и перезапустите API Kuroko. В пресете OpenRouter укажите модель и нажмите «Загрузить провайдеров». Выбранный провайдер закрепляется за пресетом. Вариант «Автоматически» включает обычную маршрутизацию OpenRouter.

SQLite создаётся при первом запуске. По умолчанию база находится в `data/kuroko.sqlite`. Разработка и запуск сборки из корня проекта используют один и тот же каталог. Переменная `DATA_DIR` позволяет выбрать другой путь. Названия секретов хранятся в базе открыто, значения шифруются AES-256-GCM. Пароли хранятся в виде хешей Argon2id.

По умолчанию ключ шифрования создаётся в `data/vault.key`. Сохраняйте резервную копию ключа отдельно от резервной копии БД. Если используется `VAULT_KEY`, сохраните то же значение для следующих запусков. При переносе данных остановите приложение и скопируйте каталог данных. Один файл базы без ключа не позволит восстановить значения секретов.

### Запуск на сервере

Запускайте сборку за HTTPS-прокси, который обслуживает фронтенд и `/api` на одном адресе. По умолчанию API слушает только `127.0.0.1`. Задайте `COOKIE_SECURE=1`, постоянный `DATA_DIR` вне каталога `dist/web` и передайте `VAULT_KEY` через хранилище секретов хоста. Для новой базы ключ можно сгенерировать командой `bun -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`. Для существующей локальной базы используйте её текущий ключ.

Приложение ограничивает попытки входа и регистрации по IP. Если прокси работает на той же машине, перезаписывает `X-Forwarded-For` и только он принимает внешние подключения, задайте `TRUST_PROXY=loopback`. При другой топологии укажите адрес или подсеть доверенного прокси. Регистрация открыта, и каждый новый аккаунт получает собственное пустое хранилище.

## Режим ведущего

Переключатель «Режим ведущего» в шапке чата применяется к новым ходам выбранного чата. Сервер выполняет инструменты, включённые в менеджере, и показывает игроку только текст, который модель передала в `publishScene`. Если модель не вызвала функцию успешно, черновик сцены не появляется в чате.

Успешная публикация сохраняет закрытые вызовы и результаты инструментов, промежуточный текст модели и необязательные заметки ведущего. Заметки передаются провайдеру модели в следующих ходах этого чата. Детали прошлых закрытых бросков ведущий может запросить через `getRollDetails`. Отключение режима оставляет закрытые записи на сервере. Чтобы проверить режим, включите инструмент броска и попросите модель сделать тайную проверку, а затем описать, что заметил персонаж.

## Миры

В «Мирах» можно создавать и редактировать карточки с аватарами, метаданными и отдельными разделами, искать по библиотеке и внутри каждого раздела. В каждом старте можно указать сценарий, приветствие и выбрать записи мира, которые относятся к началу игры.

В библиотеке поиск и сортировку можно сочетать с фильтрами по автору, тегам и наличию стартов. Карточка подходит по тегам, если содержит все выбранные. Звёздочка добавляет мир в избранное аккаунта, а переключатель «Избранное» показывает только отмеченные миры.

Кнопка «Импортировать карточку» в библиотеке открывает карточку Kuroko версии `0.1.0`. Совпадающая карточка открывается из библиотеки, а при конфликте по ID можно создать отдельную копию. Кнопка «Экспортировать JSON» в редакторе скачивает текущую валидную карточку с правками, аватарами и ссылками между записями. В файле хранится объект `Realm`. Размер JSON ограничен 8 МиБ.

Эта же кнопка принимает карточки SillyTavern в PNG и JSON. Они открываются как черновик нового мира с персонажем и стартами. Картинка из PNG становится аватаром, а каждое приветствие — отдельным стартом. Основной контекст заполняется символом `-`. Книги знаний и инструкции промпта SillyTavern в этой версии пропускаются.

| Метод и маршрут | Операция |
| --- | --- |
| `GET /api/realms` | Список с кратким описанием и количеством записей. Параметры `q`, `sort`, `limit`, `offset`, `author`, повторяемый `tag`, `starts=with` или `starts=without` и `favorites=1`. Варианты сортировки `updated`, `created`, `title-asc`, `title-desc`. Ответ `{ items, total }`. |
| `GET /api/realms/filters` | Варианты автора и тегов в библиотеке аккаунта. |
| `POST /api/realms` | Создать мир. В теле — карточка `Realm` версии `0.1.0`. |
| `GET /api/realms/:id` | Получить полную карточку с метаданными. |
| `GET /api/realms/:id/avatar` | Получить изображение мира. В списке у миров с изображением есть поле `hasAvatar`. |
| `GET /api/realms/:id/context?start=<id>` | Получить основу мира, сценарий, приветствие и выбранные записи в порядке контекста. Без `start` возвращается основа мира и пустой список записей. |
| `PUT /api/realms/:id` | Сохранить карточку. В теле — `{ revision, realm }`. |
| `PUT /api/realms/:id/favorite` | Отметить или снять отметку избранного. В теле — `{ favorite }`. Изменение хранится отдельно от карточки и её ревизии. |
| `DELETE /api/realms/:id` | Удалить мир. Параметр `revision` проверяет, что версия совпадает с открытой. |

Запросы привязаны к аккаунту. Создание, обновление и получение карточки возвращают `{ id, revision, createdAt, updatedAt, realm }`. Для маршрута используется внешний `id` из этого ответа. Поле `realm.id` остаётся идентификатором карточки и уникально в пределах аккаунта. При устаревшей ревизии сервер возвращает `409 realm_conflict`. Типы опубликованы в `@kuroko/contracts/realms`.

Поля `description`, `author`, `version`, `authorNotes`, `tags` и `avatar` опциональны. У персонажа `content` хранит полное описание, `summary` — краткое. Аватары мира и персонажей передаются как `data:` URL с JPEG, PNG или WebP длиной до 65 536 символов. Браузерный редактор сохраняет пропорции изображения и уменьшает длинную сторону до 512 пикселей или меньше в зависимости от размера файла. Нажатие на аватар в редакторе открывает изображение целиком.

Поле `order` хранит целое число от 1 до 999 999. Если его нет, используется позиция записи в исходном списке, начиная с 1. Контекст сортируется по возрастанию `order`. При совпадении номеров сначала идут персонажи, затем книга знаний и пользовательские разделы в порядке карточки. Внутри каждого списка записи с одинаковыми номерами сохраняют свою последовательность. Для самих стартов `order` управляет порядком в редакторе.

## API генерации LLM

Во вкладке «Чат» можно создать новый диалог и открыть предыдущий в списке. Текстовые сообщения, правки и удаления сохраняются в SQLite для текущего аккаунта. Каждая отправка передаёт историю выбранного диалога и новое сообщение модели из активного пресета. Ответ появляется по мере генерации.

В разделе «Инструменты» можно отдельно включить `roll_dice`, `resolveCheck`, `getRollDetails` и `test_echo` и посмотреть их параметры. Выбор сохраняется для аккаунта и применяется к следующим запросам в чате. Раскройте вызов в ответе модели, чтобы увидеть аргументы, результат или ошибку.

`roll_dice` использует движок Mayori. Он принимает дерево формул в `rolls`, короткое назначение в `purpose` и флаг `details`. Например, `{"rolls":{"attack":"2d20kh1 + 5","hit":"$attack >= 15","damage":"if($hit, 2d6! + 3, 0)"}}` бросает урон только при попадании. Доступны арифметика, логика, `kh` и `kl`, взрывы `!`, перебросы `r` и `ro`, `count`, `countFaces`, `face` и ссылки `ref([...])`. Полная трассировка хранится в истории. При `details: true` модель также получает её в ответе инструмента.

`resolveCheck` проверяет выбранную грань с модификатором против `target`. Профили `standard`, `critical` и `attack` принимают `sides` от 2 до 1 000 000, по умолчанию 20. В `critical` и `attack` максимальная грань даёт критический успех. Единица даёт критический провал в `critical` и автоматический промах в `attack`. `d20-critical` и `d20-attack` остаются профилями для d20. Все профили поддерживают обычную проверку, преимущество и помеху. Если переданы формулы урона, инструмент бросает только формулу, применимую к исходу проверки.

Броски и проверки по умолчанию отправляют модели краткий результат с `rollId`. `getRollDetails` читает по этим идентификаторам до 20 сохранённых результатов текущего чата, включая броски из предыдущих сообщений. Инструмент показывает полную трассировку по запросу и не бросает кости заново. В контекст следующих пользовательских сообщений входят краткие результаты и ссылки на разобранные броски.

`POST /api/llm/generate` использует сохранённые пресеты OpenAI, OpenRouter, Anthropic, Gemini и пользовательских OpenAI-совместимых API. Маршрут принимает сессионную cookie и заголовок `X-Kuroko-Request: 1`. Для браузерного клиента можно также передать `X-Kuroko-Account` с ID текущего аккаунта. Поле `presetId` выбирает конкретный пресет этого аккаунта. Если поле отсутствует, используется активный пресет. Форматы запроса и ответа экспортируются из `@kuroko/contracts/llm`.

```json
{
  "messages": [
    { "role": "system", "content": "Отвечай кратко." },
    { "role": "user", "content": "Опиши начало сцены на ночной станции." }
  ],
  "parameters": { "temperature": 0.7, "responseTokens": 512 },
  "stream": true
}
```

Отправляйте тело как `application/json`. Поле `parameters` переопределяет значения `responseTokens`, `temperature`, `topP`, `topK` и `contextTokens` для одного запроса. Передайте `null`, чтобы сбросить значение из пресета. При пустом лимите ответа Anthropic получает `max_tokens: 4096`, поскольку его API требует это поле. Поддержка параметров зависит от модели. `contextTokens` задаёт порог для `contextLimitExceeded`, который вычисляется по числу входных токенов из ответа провайдера. Историю передаёт клиент.

При `stream: false` (по умолчанию) API возвращает JSON с сообщением ассистента, причиной завершения и статистикой токенов, если её передал провайдер. При `stream: true` ответ приходит как `text/event-stream` с событиями `text_delta`, `tool_call` и `done`. В `done.completion` приходит итоговый объект того же формата, что и JSON-ответ. Ошибка в открытом потоке завершает его событием `error` с полями `type` и `code`. При разрыве соединения запрос к провайдеру отменяется. Тайм-аут генерации составляет 120 секунд, лимит размера запроса и ответа провайдера составляет 4 МиБ для каждого.

Ошибки HTTP API, включая ошибки генерации до открытия потока, возвращаются с HTTP-статусом и JSON-объектом с полем `code`. В ошибках конкретного поля формы также приходит `field`. Коды определены в [контракте ошибок](packages/contracts/src/errors.ts). Веб-клиент подставляет текст на выбранном языке.

Для вызова функций передайте `tools` с именами, необязательными описаниями и объектными JSON Schema в поле `parameters`. Поле `toolChoice` принимает `auto`, `none`, `required` или объект `{ "name": "имя_функции" }`. Модель возвращает вызовы в `completion.message.parts` в элементах `toolCall` с идентификатором и разобранными аргументами. Приложение проверяет аргументы, выполняет функцию и добавляет в историю целиком полученное `message`, затем по одному сообщению `{ "role": "tool", "callId": "...", "content": результат }` на каждый вызов. При ошибке функции добавьте `"isError": true`. Служебные поля Gemini и OpenRouter в сообщении ассистента нужны для продолжения диалога с этими моделями.

Для серверного прокси задайте переменные `<PROVIDER>_BASE_URL` и при необходимости `<PROVIDER>_GENERATION_PATH` из [.env.example](.env.example). Базовый URL также используется для каталога моделей. Путь генерации задаётся относительно базового URL. Для Gemini доступны подстановки `{model}` и `{method}`. Адрес задаёт администратор сервера, поскольку на него будут отправлены сохранённые ключи этого провайдера.

Адаптеры используют [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [OpenRouter Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request), [Anthropic Messages](https://platform.claude.com/docs/en/build-with-claude/streaming) и [Gemini GenerateContent](https://ai.google.dev/api/generate-content).

## Скрипты запуска

Скрипты лежат в `scripts/`. На Windows можно открыть нужный `.bat` двойным кликом или вызвать из терминала. На Linux и macOS можно запускать `.sh` напрямую или через `sh`. Ниже приведены команды из корня проекта. Перед первым запуском установите зависимости командой `bun install`.

| Задача | Windows | Linux и macOS |
| --- | --- | --- |
| Запустить API и фронтенд для разработки | `.\scripts\dev.bat` | `sh ./scripts/dev.sh` |
| Запустить только API | `.\scripts\dev-api.bat` | `sh ./scripts/dev-api.sh` |
| Запустить только фронтенд | `.\scripts\dev-web.bat` | `sh ./scripts/dev-web.sh` |
| Собрать проект | `.\scripts\build.bat` | `sh ./scripts/build.sh` |
| Запустить готовую сборку | `.\scripts\start.bat` | `sh ./scripts/start.sh` |

## Структура

Устройство модулей фронтенда и правила добавления функций описаны в [архитектурном гайде](docs/frontend-architecture.md).

```text
apps/
  api/src/
    app.ts, server.ts       # Настройка Express и запуск
    http/                   # Подключение маршрутов API
    auth/, chat-settings/   # Маршруты и хранилища аккаунта, сессий и настроек чата
    connection/             # Пресеты, хранилище ключей и каталоги моделей
    llm/                    # Генерация, протоколы провайдеров и поток ответов
    storage/                # Открытие SQLite, миграции, загрузка ключа хранилища
  web/
    src/
      main.tsx              # Точка входа React
      app/                  # Оболочка, гостевой экран и навигация
      platform/             # Сессия и запуск моделей
      modules/, core/       # Реестр и состав встроенных модулей
      features/             # Экраны, вкладки и модели отдельных функций
      shared/               # HTTP-клиент, тема, уведомления и общие стили
    vite.config.ts          # Сборка и прокси для разработки
packages/
  contracts/src/            # Форматы данных API и общая валидация
dist/
  server.js                 # Серверный бандл
  web/                      # Статические файлы фронтенда
```

При изменении формата запроса или ответа начните с соответствующего модуля в `packages/contracts/src`. На сервере маршруты разбирают входные данные и формируют HTTP-ответы, а хранилища выполняют SQL и транзакции. Миграции находятся в `apps/api/src/storage/migrations.ts`.

Для нового провайдера добавьте его параметры в `packages/contracts/src/connectionSettings.ts` и опишите адрес запроса, авторизацию и формат каталога в `apps/api/src/connection/providerModels.ts`. Формы берут список провайдеров и диапазоны параметров из общего контракта.

На фронтенде модели Effector находятся рядом с компонентами соответствующей функции. Компоненты читают сторы и отправляют события через `useUnit`. Запуск приложения создаёт scope в `apps/web/src/main.tsx`. Там же подключены события браузера для навигации и сохраняемых предпочтений. При завершении сессии модели сбрасывают данные аккаунта и отменяют связанные запросы.

Запросы подключения собраны в `apps/web/src/features/connection/connectionApi.ts`. Пресеты, черновики и ключи находятся в `model.ts` той же папки, каталоги — в `modelCatalog.ts`. В чате `chatApi.ts` загружает и сохраняет диалоги и читает поток ответа. Модели можно тестировать через `fork` и `allSettled` командой `bun test`.

После сборки один процесс Express обслуживает фронтенд и API по адресу <http://localhost:3000>. Если перенести готовый каталог `dist/` отдельно, для запуска достаточно Bun. Из этого каталога выполните `bun ./server.js --serve-web`.
